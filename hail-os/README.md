# Restaurant OS — نظام تشغيل المطعم

نظام تشغيل متكامل لمطعم: من مسح رمز QR على الطاولة، إلى المطبخ والصالة
والكاشير، وصولاً إلى تحليلات المدير. **بدون تنصيب وبدون خطوة بناء** —
كل الشاشات تتزامن لحظياً **بين كل الأجهزة** عبر قاعدة مشتركة على Supabase
(الإعداد في `assets/js/data/backend.js`)، وعند تعطيلها يعمل النظام
بالتخزين المحلي متزامناً بين تبويبات الجهاز الواحد.

---

## التشغيل

### الطريقة الأسرع
انقر مرّتين على:

```
تشغيل-النظام.cmd
```

سيفتح المتصفح على `http://localhost:3000` وتظهر في نافذة الأوامر عناوين
الشبكة المحلية لاستخدامها من الجوال.

### يدوياً

```bash
node server.mjs 3000
```

يتطلب Node.js فقط (بدون `npm install` — لا توجد أي حزم خارجية).

### التشغيل من الجوال ومسح رموز QR
1. اربط الجوال بنفس شبكة الواي فاي.
2. خذ العنوان الظاهر بصيغة `http://192.168.x.x:3000` من نافذة الأوامر.
3. افتحه على الجوال، أو امسح رمز QR الخاص بالطاولة من مركز الإطلاق.

## الشاشات

| الشاشة | الرابط | لمن |
|---|---|---|
| مركز الإطلاق | `/` | البوابة + مولّد رموز QR + أدوات العرض |
| منيو الزبون | `/menu.html?t=3` | الزبون على الطاولة رقم 3 |
| طلب سفري / توصيل | `/menu.html` | زبون بلا طاولة |
| شاشة المطبخ (KDS) | `/kds.html` | الشيف والباريستا |
| إدارة الصالة | `/floor.html` | النُّدُل وكابتن الصالة |
| الكاشير | `/cashier.html` | نقطة البيع والتحصيل |
| لوحة الإدارة | `/admin.html` | المدير |

### الأرقام السرية للطاقم

| الموظف | الدور | الرقم |
|---|---|---|
| أحمد الخطيب | مدير | `1111` |
| سارة العمري | كاشير | `2222` |
| محمود الزعبي | نادل | `3333` |
| ليان القضاة | نادل | `3434` |
| عمر الشوابكة | شيف | `4444` |
| رنا حدّاد | باريستا | `5555` |

كل دور يرى الشاشات المسموح له بها فقط.

## سيناريو العرض (٥ دقائق)

1. **افتح مركز الإطلاق** واضغط **«تجربة التنبيهات»** — يسمع الحضور بصمة
   صوتية مختلفة لكل حدث.
2. **افتح شاشتين جنباً إلى جنب**: `menu.html?t=3` و `kds.html`.
3. من شاشة الزبون: اختر صنفاً، حدّد الخيارات، أضِف للسلة، **أرسل الطلب**.
   → يظهر فوراً في المطبخ مع صوت تنبيه ومؤقّت يعدّ.
4. من المطبخ: **اقبل → ابدأ التحضير → جاهز**.
   → شاشة الزبون تتحرّك على مسار التتبّع تلقائياً بلا تحديث.
5. من شاشة الزبون: اضغط **«اطلب الفاتورة»** أو أي نداء خدمة.
   → يصل النداء إلى `floor.html` بأولوية ولون تصعيد.
6. من الكاشير: افتح **الفواتير المفتوحة** → **تحصيل** → طبّق خصماً واختر
   نقداً وأدخل المبلغ المستلم → يحسب الباقي ويُقفل الجلسة.
7. من لوحة الإدارة: أرِ **لوحة القيادة** — المبيعات تتحدّث لحظياً، ومقارنة
   اليوم بأمس بنفس التوقيت، والأكثر مبيعاً، وتنبيه المخزون.
8. شغّل **المحاكي الحيّ** من مركز الإطلاق واترك الشاشات تعمل وحدها أثناء
   الحديث — طلبات ونداءات تتوالى تلقائياً.

## ما الذي يقدّمه النظام

### للزبون
المنيو الرسمي كاملاً (**٢٠٩ صنف / ٢٦ قسم**) بالصور والأسعار، بحث عربي ذكي
يتجاهل التشكيل ويوحّد الهمزات، خيارات لكل صنف (الحجم، النضج، الحليب،
الإضافات)، سلة، طلب متعدّد الجولات على نفس الجلسة، تتبّع حيّ لحالة الطلب،
نداءات خدمة بلمسة، وفاتورة لحظية. يمكن لكل شخص على الطاولة كتابة اسمه مع طلبه ليظهر حسابه منفصلاً عند الكاشير.

### للمطبخ
توجيه تلقائي لكل صنف إلى محطته (ساخن، شوي، فرن، بارد، بار، حلويات، معسل)،
عرض بالأعمدة أو الشبكة، مؤقّت لكل طلب مع تصعيد لوني وصوتي عند التأخّر،
تعليم الأصناف واحداً واحداً، وفلترة حسب المحطة.

### للصالة
خريطة طاولات بأربع مناطق وحالات (فارغة، مشغولة، محجوزة، تحتاج تنظيف)،
نداءات مرتّبة بالأولوية مع مهلة استجابة، قائمة الأطباق الجاهزة للتقديم،
فتح وإغلاق الجلسات، والحجوزات.

### للكاشير
قبول أو رفض الطلبات، فواتير الطاولات المفتوحة، تحصيل نقدي/بطاقة/محفظة مع
خصم وبقشيش وحساب الباقي، وتقسيم الفاتورة تلقائياً بالأسماء لتحصيل كل شخص منفصلاً، وطلب يدوي سريع،
طباعة الفواتير، وتقفيل الوردية.

### للمدير
مؤشرات حيّة ومقارنة عادلة مع أمس بنفس التوقيت، مبيعات على مدار الساعة،
توزيع الأقسام، الأكثر مبيعاً، حِمل المحطات، سجلّ أحداث كامل، تعديل أسعار
المنيو وإخفاء الأصناف النافدة، مخزون مرتبط بالأصناف يُخصم آلياً مع تنبيه
عند حدّ إعادة الطلب، إدارة الطاقم والصلاحيات، تقارير وتصدير CSV، ونسخ
احتياطي واستيراد.

## البنية التقنية

```
hail-os/
├─ index.html · menu.html · kds.html · floor.html · cashier.html · admin.html
├─ server.mjs              خادم ملفات بلا حزم خارجية
├─ تشغيل-النظام.cmd
└─ assets/
   ├─ css/  theme.css (نظام التصميم) · app.css (المكوّنات) · fonts.css
   ├─ fonts/  Alexandria + IBM Plex Sans Arabic (محلية، تعمل بلا إنترنت)
   ├─ menu/   ٣٥ صورة من المنيو الرسمي
   └─ js/
      ├─ core/   store · bus عبر BroadcastChannel · notify · fx · qr · shell · util
      ├─ data/   menu (المنيو الرسمي) · seed (بيانات الديمو والمحاكي)
      └─ app/    customer · kds · floor · cashier · admin · launcher
```

- **بلا حزم**: لا `node_modules` ولا خطوة بناء. JavaScript وحدات أصلية.
- **التخزين**: `localStorage` — مصدر واحد للحقيقة، وكل تعديل يمرّ عبر
  `commit()` الذي يعيد قراءة أحدث نسخة قبل الكتابة فلا تدهس شاشة نتيجة أخرى.
- **المزامنة**: بين الأجهزة عبر Supabase (`core/store.js` — التزام برقم
  مراجعة يمنع تضارب جهازين)، وبين تبويبات الجهاز الواحد عبر
  `BroadcastChannel` مع احتياطي عبر أحداث `storage`.
- **الأصوات**: مولّدة داخلياً بـ WebAudio — لا ملفات صوتية إطلاقاً.
- **رموز QR**: مولّد كامل مكتوب من الصفر (Reed–Solomon + اختيار قناع تلقائي)،
  يدعم الإصدارات ١–١٠ ومستويات التصحيح L/M/Q/H.
- **إمكانية الوصول**: RTL كامل، تباين مرتفع، أهداف لمس ≥ 44px، احترام
  `prefers-reduced-motion`، وحالات تُوصَّف بالنص والأيقونة لا باللون وحده.

## ملاحظات

- **الأسعار** بالدينار الأردني وتُخزَّن بالفلس (١٠٠٠ فلس = ١ دينار) لتفادي
  أخطاء الكسور العشرية. الضريبة **٧٪** كما في المنيو الرسمي، والخدمة **١٠٪**
  على الصالة وكلاهما قابل للتعديل من الإعدادات.
- **صنف بيتزا واحد** في المنيو الرسمي ظهر سعره وصورته دون اسم واضح، وأُدرج
  في النظام موسوماً بذلك بدل تخمين الاسم.
- **بيانات الديمو** تُولَّد تلقائياً عند أول فتح: يوم أمس كاملاً للمقارنة،
  واليوم حتى الساعة الحالية، وطاولات مشغولة وطلبات حيّة في المطبخ. يمكن
  إعادة توليدها أو مسحها كلياً من الإعدادات.
- لإفراغ كل شيء والبدء من الصفر: **الإعدادات ← مسح كل البيانات**.
