# هيل كافيه — الموقع ونظام التشغيل

منظومة متكاملة لمقهى هيل: موقع تعريفي للزبائن، ومنيو طلب من الطاولة عبر QR،
وشاشات تشغيل (مطبخ، صالة، كاشير، إدارة) **تتزامن لحظياً بين كل الأجهزة** عبر
قاعدة مشتركة على Supabase — طلب من جوال الزبون يظهر على شاشة المطبخ خلال
ثانيتين، من أي مكان فيه إنترنت.

**بدون أي حزم خارجية** — Node.js فقط للتشغيل المحلي، وكل النشر ملفات ثابتة.

---

## خريطة المشروع

```
Hail-Cafe/
├─ docs/                  ← جذر النشر — لا تعدّل يدوياً ما هو مولَّد
│  ├─ index.html          ← الصفحة الرئيسية للزبون (اطلب / احجز / الموقع)
│  ├─ menu.html           ← منيو التصفح — يولَّد من منيو النظام (لا تعدّله يدوياً)
│  └─ hail-os/            ← نسخة النشر من النظام — تولَّد من hail-os/
├─ hail-os/               ← ✏️ المصدر الوحيد للنظام — كل التعديل هنا
│  ├─ *.html              ← الشاشات
│  └─ assets/js/
│     ├─ data/menu.js     ← ✏️ المنيو الرسمي: الأقسام والأصناف والأسعار
│     ├─ data/backend.js  ← إعدادات المزامنة (مفتاح النشر العلني فقط)
│     ├─ core/store.js    ← الحالة + المزامنة السحابية + التقارير
│     └─ app/*.js         ← منطق كل شاشة
├─ supabase/migrations/   ← تجهيز قاعدة المزامنة (يُطبَّق مرة واحدة لكل بيئة)
├─ tools/
│  ├─ sync-site.mjs       ← npm run sync — يبني docs/ من المصدر
│  └─ gen-public-menu.mjs ← يولّد docs/menu.html من menu.js
├─ tests/                 ← npm test — بدون أي تنصيب
├─ server.mjs             ← خادم محلي بلا تبعيات (نسخة ثانية داخل hail-os/)
└─ HAIL-OS.cmd            ← تشغيل النظام محلياً بنقرة واحدة
```

## التشغيل المحلي

انقر مرّتين على `HAIL-OS.cmd`، أو:

```bash
node hail-os/server.mjs 3000
```

تظهر عناوين الشبكة في نافذة الأوامر — افتح `http://192.168.x.x:3000` من
الجوال لتجربة QR فعلياً. لمعاينة الموقع التعريفي محلياً:
`node server.mjs 8787` ثم افتح `/docs/`.

## الشاشات والأرقام السرية

| الشاشة | الرابط | الدخول |
|---|---|---|
| مركز الإطلاق | `/` | — |
| منيو الزبون | `/menu.html?t=3` | — |
| شاشة المطبخ | `/kds.html` | شيف `4444` · باريستا `5555` |
| إدارة الصالة | `/floor.html` | نادل `3333` / `3434` |
| الكاشير | `/cashier.html` | كاشير `2222` |
| لوحة الإدارة | `/admin.html` | مدير `1111` |

المدير (`1111`) يدخل كل الشاشات. الطاقم يُدار من الإدارة ← الطاقم،
ويُخزَّن في الحالة المشتركة.

## أشهر التعديلات

### تعديل المنيو (أصناف / أسعار / أقسام)
1. عدّل `hail-os/assets/js/data/menu.js` فقط.
2. `npm run sync` — يعيد بناء `docs/` كاملاً.
3. `git push` — ينشر تلقائياً.

الاختبارات تفشل عمداً إذا نسيت خطوة sync.

### تعديل شاشة أو تصميم
عدّل داخل `hail-os/` ثم `npm run sync` ثم push. لا تعدّل `docs/hail-os/`
مباشرة — سيمسحه أول sync.

### الموقع التعريفي
`docs/index.html` يُعدَّل مباشرة (غير مولَّد). `docs/menu.html` مولَّد —
قالبه داخل `tools/gen-public-menu.mjs`.

### إضافة شاشة جديدة
1. أنشئ `hail-os/الاسم.html` بنسخ بنية شاشة قريبة.
2. أنشئ `hail-os/assets/js/app/الاسم.js`: ابدأ بـ `boot()` من
   `core/shell.js` واشترك في التغييرات عبر `watchNotifications`.
3. كل قراءة وكتابة عبر دوال `core/store.js` حصراً — فتحصل على المزامنة
   بين الأجهزة والتخزين والتقارير مجاناً.

## المزامنة السحابية (Supabase)

- كل الشاشات تتشارك وثيقة حالة واحدة عبر دالتين آمنتين
  (`hail_os_state_get` / `hail_os_state_commit`) بفحص رقم مراجعة يمنع
  تضارب كتابة جهازين، مع دمج تلقائي للجلسات المكررة وأرقام الطلبات.
- المتصفح يحمل **مفتاح النشر العلني فقط** — الوصول المباشر للجداول ممنوع
  بـ RLS، والاختبارات تفشل إذا تسرّب مفتاح سري لملفات المتصفح.
- **بيئة جديدة**: أنشئ مشروع Supabase، نفّذ ملف
  `supabase/migrations/…hail_os_shared_state.sql` من محرر SQL، وحدّث
  الرابط والمفتاح في `hail-os/assets/js/data/backend.js`.
- **عمل بلا إنترنت**: ضع `enabled: false` في `backend.js` — يعمل النظام
  بالتخزين المحلي (`localStorage` + `BroadcastChannel`) ويتزامن بين
  تبويبات الجهاز الواحد فقط.

## سيناريو العرض (٥ دقائق)

1. **افتح مركز الإطلاق** واضغط **«تجربة التنبيهات»** — بصمة صوتية لكل حدث.
2. **افتح شاشتين جنباً إلى جنب**: `menu.html?t=3` و `kds.html`
   (أو المنيو من جوالك والمطبخ على الشاشة — يتزامنان عبر الإنترنت).
3. من الزبون: اختر صنفاً وخياراته، أضِف للسلة، **أرسل الطلب**
   → يظهر فوراً في المطبخ مع تنبيه ومؤقّت.
4. من المطبخ: **اقبل → ابدأ التحضير → جاهز**
   → شاشة الزبون تتقدّم على مسار التتبّع بلا تحديث.
5. من الزبون: **«اطلب الفاتورة»** أو أي نداء خدمة
   → يصل إلى `floor.html` بأولوية ولون تصعيد.
6. من الكاشير: **الفواتير المفتوحة → تحصيل** — خصم، نقدي وحساب الباقي،
   أو تقسيم بالأسماء ليدفع كل شخص حصته.
7. من الإدارة: لوحة القيادة — مبيعات لحظية، مقارنة بأمس بنفس التوقيت،
   الأكثر مبيعاً، تنبيه المخزون.
8. شغّل **المحاكي الحيّ** من مركز الإطلاق واترك الشاشات تعمل وحدها.

## ما الذي يقدّمه النظام

- **للزبون**: المنيو كاملاً (٢٠٩ صنف / ٢٦ قسم) بتصميم فاخر يتبع الثيم، بحث
  عربي يتجاهل التشكيل ويوحّد الهمزات، خيارات لكل صنف، طلب متعدد الجولات،
  تتبّع حيّ، نداءات خدمة، وفاتورة لحظية مع اسم لكل شخص لتقسيم الحساب.
- **للمطبخ**: توجيه تلقائي للمحطات (ساخن، شوي، فرن، بارد، بار، حلويات،
  معسل)، مؤقّت وتصعيد لوني وصوتي للمتأخر، تعليم الأصناف واحداً واحداً.
- **للصالة**: خريطة طاولات بأربع مناطق وحالاتها، نداءات بالأولوية ومهلة
  استجابة، الجاهز للتقديم، الجلسات والحجوزات.
- **للكاشير**: قبول/رفض، فواتير مفتوحة، تحصيل بخصم وبقشيش وحساب الباقي،
  تقسيم بالأسماء، طلب يدوي، طباعة، تقفيل وردية.
- **للمدير**: مؤشرات حيّة ومقارنة عادلة بأمس بنفس التوقيت، مبيعات بالساعة،
  الأكثر مبيعاً، تعديل الأسعار وإخفاء النافد، مخزون يُخصم آلياً بتنبيه حدّ
  الطلب، إدارة طاقم، تقارير وتصدير CSV، نسخ احتياطي واستيراد.

## تفاصيل تقنية تهم من يطوّر

- **الأسعار** بالدينار الأردني تُخزَّن بالفلس (١٠٠٠ فلس = دينار) لتفادي كسور
  العشرية. الضريبة ٧٪ والخدمة ١٠٪ على الصالة — قابلة للتعديل من الإعدادات.
- **الأصوات** مولّدة بـ WebAudio، و**رموز QR** مولّد كامل مكتوب من الصفر
  (Reed–Solomon، إصدارات ١–١٠) — لا ملفات صوت ولا مكتبات.
- **الخطوط** محلية (Alexandria + IBM Plex Sans Arabic) — تعمل بلا إنترنت.
- **إمكانية الوصول**: RTL كامل، أهداف لمس ≥ 44px، احترام
  `prefers-reduced-motion`، وحالات تُوصَّف بالنص لا باللون وحده.
- **بيانات الديمو**: تُدار من شاشة الإدارة ← الإعدادات (توليد بيانات عرض،
  محاكي حركة حيّة، مسح كل شيء للبدء من الصفر).

## استكشاف الأخطاء

- **تعديل لا يظهر**: كاش المتصفح (Ctrl+Shift+R)، أو نسيت `npm run sync`.
- **Netlify متوقف (انتهاء رصيد)**: GitHub Pages لا يتأثر ويظل ينشر؛ يعود
  Netlify تلقائياً مع أول push بعد تجدد الرصيد.
- **لا تزامن بين جهازين**: تحقق من الإنترنت، وافحص `store.syncStatus()`
  من كونسول المتصفح.
